# Dayo 設計書

## 概要と目的

データはiCloudリマインダーとGoogleカレンダーに置いたまま、表示と入力だけを自作するMac/iPhoneアプリを作る。純正リマインダー・カレンダーはUIが不満だが、同期・通知・共有の仕組み自体は信頼できるため、そこは作らない。

解決したい要件は3つ。

1. **Todoの共有**: 家族・関係者（全員iPhone）とTodoリストを共有する
2. **定期リマインダーの簡単入力**: 「毎週月曜 9時 ゴミ出し」のような1行で繰り返し設定まで完了する
3. **カレンダーとリマインダーの同時表示**: 予定とTodoを1本の時間軸で見る

## スコープとMVP

対象はmacOSとiOS。SwiftUIのマルチプラットフォームターゲットでコードを共有し、Mac専用機能（キー操作）だけ分ける。

| 区分 | 内容 |
| --- | --- |
| MVPに入れる | 統合タイムライン（日・3日・週）、クイック入力（繰り返し対応）、完了チェック、ドラッグでの日時変更 |
| MVP後 | 月表示、ウィジェット、ショートカット（App Intents）、LLMによる入力解釈 |
| 作らない | 同期・通知・共有メンバー管理（純正アプリ/iCloudに任せる）、リマインダーリスト別の一覧と共有リストの目印（リストごとに見るのは純正リマインダーに任せる）、独自サーバー、担当者割当て・サブタスク、メニューバー常駐 |

配布は自分用。Mac はこの Mac 専用の自己署名証明書で署名して `/Applications` に入れる（アドホック署名だと作り直すたびに別のアプリ扱いになり、カレンダー / リマインダーの許可を聞き直されるため）。iPhone は Xcode から直接入れるか TestFlight。共有相手は純正リマインダーで使えるため、アプリを配る必要はない。

アプリアイコンはカレンダーの紙の形。Mac では起動している間、Dock のアイコンを今日の日付にする。終了中の Dock・Finder・iPhone は固定の図柄のまま（アプリが自分で描き替えられるのは、起動中の Dock だけのため）。

## データモデル

アプリ内部では予定とリマインダーを `TimelineItem` に統一し、画面はこれだけを扱う。永続化はしない（正はEventKit側）。

```swift
enum ItemKind { case event, reminder }

struct TimelineItem: Identifiable {
    let id: String              // 画面用の一意キー。繰り返し予定は回ごとに異なる
    let calendarItemIdentifier: String  // EventKit から引き直すキー（繰り返しの全回で共通）
    let kind: ItemKind
    var title: String
    var start: Date?            // event: startDate / reminder: dueDate
    var end: Date?              // eventのみ
    var isAllDay: Bool
    var isCompleted: Bool       // reminderのみ
    var sourceName: String      // リスト名 or カレンダー名
    var accountName: String     // iCloud / Google などアカウント名（同名カレンダーの区別）
    var color: CGColor
    var recurrence: RecurrenceSpec?  // 編集できる形の繰り返し。表せない規則は nil
    var hasRecurrence: Bool     // 何らかの繰り返しがあるか（nil かつ true ならカスタム規則）
    var notes: String?
    var calendarIdentifier: String   // 保存先リスト／カレンダーの識別子
    var isVirtual: Bool         // 繰り返しリマインダーの将来回を画面用に展開したもの（EventKit に実体が無い）
}
```

`TimelineItem` は EventKit の型を持たない（`EKRecurrenceRule` も `RecurrenceSpec` に変換する）。画面とテストが EventKit に触れずに済ませるため。年次や終了付きなど `RecurrenceSpec` で表せない規則は「カスタム」として表示だけし、編集時に触らない。

| 項目 | EKEvent | EKReminder |
| --- | --- | --- |
| start | startDate | dueDateComponents → Date |
| end | endDate | なし |
| 完了 | なし | isCompleted |
| 日付なし | なし | あり（タイムラインには表示しない。純正リマインダーで管理する） |
| 繰り返し | recurrenceRules | recurrenceRules |

注意点：繰り返し予定は期間指定で展開された各回が返り、全回が同じ `calendarItemIdentifier` を持つため `id` は開始時刻を付けて区別する。一方、繰り返しリマインダーは「次の1回」だけが存在する。それより先の回は規則から計算した表示用アイテム（`isVirtual`）として出す。実体が無いので薄色にし、完了・移動・編集はできない。展開の規則:

- 起点は「いま有る次の1回」の期日。隔週・3日ごとなどの間隔はそこから数える。隔週の週の境目は OS の週の始まりではなく月曜で数える（設定で回が変わらないようにするため）
- 出すのは現在時刻より後の回だけ。期限切れのまま残っている繰り返しの、過ぎた日時の回は「これから来る回」ではないので出さない。終日の回は時刻が無いので今日の分まで出す
- このアプリで編集できない形の規則（年次・終了付きなど）は、正しく計算できる保証が無いので展開しない

## 画面構成

中心は「今日」を開いた瞬間に予定とTodoが1列で見えるタイムライン。入力はどの画面からでも同じクイック入力欄を使う。

日表示・3日表示・週表示は別の画面ではなく、同じタイムラインをサイドバーの「日表示」「3日表示」「週表示」で切り替える。違いは並べる日の列の数（1・3・7）だけで、時間帯の畳み込み・完了チェック・ドラッグ・詳細編集は共通。並べて置かないのは、同じ時間軸を 2 つ見せても情報が増えず、週の 1 列が狭くなるだけだから。

表示を切り替えたとき、いま見ている範囲に今日があれば切り替えた先でも今日を基準にする（日表示は今日、3日表示は今日が左端、週表示は今週）。今日が無ければ、いまの基準の日のまま切り替える。

| 画面 | 内容 | Mac | iPhone |
| --- | --- | --- | --- |
| 今日タイムライン | 中央は Apple カレンダーの日表示のような時間軸グリッド（時刻の目盛り上に予定をブロック、リマインダーを時刻位置のチェック付き行として配置、重なりは横に並べる）。設定した一日の開始・終了（既定 7:00〜23:00）の外に予定もリマインダーも無ければ、その時間帯は帯 1 本に畳む（クリックで開く）。上部に期限切れ（1 行に タイトル・期日・リスト名）、その下に 3日表示・週表示と同じ曜日と日付の見出し（今日を強調）、時間軸のすぐ上に終日欄。終日欄は空でも常に出す（ダブルクリックでの登録と、時間軸からのドラッグの落とし先になるため）。期日なしのリマインダーは表示しない。リマインダーはその場で完了チェック。繰り返しのある項目は、右上（1 行の項目は右端）に繰り返しの印を出す。先の日を開けば繰り返しリマインダーの将来回も薄色で出る | メインウィンドウ（サイドバーの「日表示」） | ホームタブ |
| 週表示 | Apple カレンダーの週表示と同じ形。7日分の列を並べ、時刻の目盛りは左に1本、上に曜日と日付（今日を強調）。終日の項目はその下の帯で、複数日にまたがるものは列をつなぐ。日をまたぐ時刻付きの予定は日ごとに切って出す。時間帯の畳み込みは全部の日に何も無い時間帯だけ。週の始まりは OS の設定に従う。今週を見ているときは期限切れを日表示の今日と同じ内容で上部に出す。繰り返しリマインダーの将来回は薄色。ドラッグは別の日へも動かせる（横は日単位、縦は15分刻み） | メインウィンドウ（サイドバーの「週表示」） | 未対応（日表示のみ） |
| 3日表示 | 週表示と同じ形で、基準の日を左端に 3 日分の列を並べる（今日を開くと 今日・明日・明後日）。週表示より 1 列が広い。前後の移動は 1 日ずつ。期限切れは 3 日の中に今日があるときに出す。「今日」は今日を左端にする（ボタンは今日が左端でないときに出る）。日付が変わったときは、今日が左端にあるときだけ新しい今日へ追従する（自分でずらした並びは動かさない） | メインウィンドウ（サイドバーの「3日表示」） | 未対応（日表示のみ） |
| クイック入力 | 1行入力。入力中に解釈結果（日時・繰り返し・リスト）をチップでプレビュー、Enterで登録 | メインウィンドウ上部の常設バー | 画面下部の常設バー |
| 詳細編集 | タイトル・URL（予定のみ）・日時・繰り返し・メモ・リスト。URL の欄は空でも常に出し、ブラウザで開ける URL なら隣のボタンで開く。予定に場所があれば、見るだけの行として「場所」の横に出し、押すと Google マップの検索を開く。1 行に入らない住所は、最初の「,」までを 1 行目、残りを 2 行目にする（場所を直すのは純正カレンダーに任せ、保存時は元のまま残す）。Google カレンダーがメモの末尾に足すビデオ会議の案内は、メモ欄には出さず「ビデオ会議」の参加リンクとして出す（純正カレンダーと同じ見え方。案内は Google が管理する部分なので、保存時は元のまま残す）。繰り返しは「この回のみ / 以降すべて」を選択。同じ画面を新規登録にも使い、そのときは一番上で 予定 \| リマインダー を選ぶ（直近に登録した種別から始まる） | ポップオーバー（項目を右クリック） | シート（項目をタップ） |

マウス操作（Mac）は Apple カレンダーに寄せる。項目の上の普通のクリックは、その項目を選択するだけにする（キー操作の選択と同じもの）。編集を開くのは右クリックにして、ドラッグやダブルクリックと取り違えて開くのを避ける。ダブルクリックは項目の上でも新規登録になる（同じ時間に予定があっても登録できるように）。

| 操作 | 結果 |
| --- | --- |
| 項目をクリック | その項目を選択する（繰り返しリマインダーの将来回は選択できない） |
| 項目を右クリック | その項目を選択して、詳細編集を開く |
| 時間軸をダブルクリック（項目の上でも） | その日時（15 分刻み）で新規登録を開く。予定は 1 時間。タイトルを入れずに閉じれば何も作らない。リマインダーのチェックの丸の上は除く |
| 終日欄をダブルクリック（項目の上でも） | その日の終日として新規登録を開く。リマインダーのチェックの丸の上は除く |
| 時刻付きの項目をドラッグ | 時刻を変える。3日表示・週表示では別の日へも動かせる |
| 終日の項目を終日欄の中でドラッグ（3日表示・週表示） | 日単位で動かす。複数日にまたがる予定は長さを保つ |
| 終日の項目を時間軸へドラッグ | 落とした日時からの時刻付きにする（予定は 1 時間、リマインダーは期日） |
| 時刻付きの項目を終日欄へドラッグ | 落とした日の終日にする |

キー操作（Mac）。キーはすべて小文字で書く（大文字は Shift を押す意味になるので、Shift は明示する）。`j`/`k`/`h`/`l` で項目を選び、選択中の項目はアクセント色の枠で示す。選択はキーでだけ動く。

| キー | 動作 |
| --- | --- |
| `j` / `k`（`↓` / `↑` でも同じ） | 選択を下 / 上の項目へ（期限切れ → 終日 → 時刻順）。何も選択していなければ、今日（見えていなければ最初の日）の列の先頭 / 末尾を選ぶ |
| `h` / `l`（`←` / `→` でも同じ） | 3日表示・週表示: 隣の、項目のある日の列へ（開始時刻が近い項目を選ぶ）。その方向に項目が無ければ、週表示は前 / 次の週へ移り、3日表示は 1 日ずれて新しく見えた日の項目を選ぶ（その日が空なら、画面に残っている選択はそのまま。押し続ければ項目のある日まで進む）。日表示: 前 / 次の日へ |
| `shift+j` / `shift+k`（`shift+↓` / `shift+↑` でも同じ） | 選択中の時刻付きの項目を、次 / 前の 15 分の区切りへ動かす（日の外へは出さない） |
| `shift+h` / `shift+l`（`shift+←` / `shift+→` でも同じ） | 選択中の項目を前 / 次の日へ動かす（時刻付きは同じ時刻のまま、終日は長さを保つ）。行き先が表示中の日の外なら、表示も項目の見える範囲へ移る（日表示・3日表示は 1 日、週表示は前 / 次の週） |
| `space` | 選択中のリマインダーを完了 / 未完了 |
| `return` | 選択中の項目の詳細編集を開く |
| `d` | 選択中の項目を削除する。必ず確認を挟む（同期先からも消えるため。`return` で削除、`esc` で取り消し）。繰り返しの予定は「この回のみ / 以降すべて」を聞く。削除後は同じ列の次（無ければ前）の項目を選ぶ。読み取り専用の項目には何もしない |
| `esc` | 選択を解除。入力欄では入力欄を抜ける |
| `t` | 今日へ |
| `⌘n` | 入力欄へフォーカス |
| `⌘1` / `⌘2` / `⌘3` | 日表示 / 3日表示 / 週表示 |
| `⌃⌘s` | サイドバーを出す / 隠す |
| `⌘←` / `⌘→` | 前 / 次の日（週表示では週。3日表示は 1 日ずつ） |
| `⌘r` | 最新の状態に更新する。同期元（Google カレンダーなど）の取り込みを OS に頼み、表示を読み直す。普段の同期の間隔は OS のアカウント設定が決めていて、Dayo は届いた変更を表示するだけなので、待たずに見たいときに使う。前後移動のボタンの左に「更新中」を出し、取り込んだ変更が届いて表示を読み直したら消す。取り込みの完了は OS から知らされないので、10 秒待っても変更が届かなければ、何も出さずに消す（同期元に変更が無かった場合と取り込めなかった場合の区別が付かないため） |
| `?` | キー操作の一覧を出す / 閉じる（`esc` とクリックでも閉じる） |

- 修飾キーなしのキーと `⌘←` / `⌘→` は、入力欄や詳細編集で文字を打っている間は普通の文字入力・カーソル移動のまま。そのため起動時のフォーカスは入力欄ではなくタイムラインに置く。
- 繰り返しリマインダーの将来回（薄色）は操作できないので選択されず、飛ばす。
- キーでの移動はドラッグと同じ扱い。繰り返しの予定は「この回のみ / 以降すべて」を聞き、読み取り専用の項目と期限切れ欄の項目は動かない。選択は動かした項目に付いたまま。ドラッグで動かせるのは表示中の日の中だけで、表示の外へ動かせるのはキーだけ。
- 選択した項目が画面の外なら、見える位置まで最小限スクロールする。表示の切替や日の移動で画面から消えたら、選択は解除する。
- `⌘n` は既定の「新規ウインドウ」を置き換える（ウインドウは 1 つで足りるため）。
- 詳細編集のメモで `tab` を押すと保存ボタンへ進む（メモは最後の入力欄なので、タブ文字は入れない）。`shift+tab` は前の入力欄へ戻る。メモにフォーカスがある間は、メモ欄をアクセント色の枠で示す（空のメモはカーソルが見えにくいため）。保存ボタンでは `space` か `return` で保存する。
- 詳細編集では、どの入力欄にいても `⌘return` で保存する（メモでは `return` が改行になるため）。

## クイック入力パーサー仕様

日本語1行を「繰り返し・日付・時刻・リスト・種別」に分解し、残りをタイトルにする。MVPはルールベース（正規表現＋辞書）で作り、入力→期待結果のテーブルテストで拡張する。

```swift
struct ParsedInput {
    var title: String
    var kind: ItemKind            // 既定 reminder
    var date: DateComponents?     // 参照日で解決済みの年月日
    var time: DateComponents?
    var endTime: DateComponents?  // 「10時-11時」の終了側。eventのとき使う
    var recurrence: RecurrenceSpec?
    var listName: String?
}
```

繰り返しは `EKRecurrenceRule` ではなく自前の `RecurrenceSpec`（頻度・間隔・曜日・第n週・日）で持つ。`EKRecurrenceRule` は値として比較できずテーブルテストに向かないため。`EKRecurrenceRule` への変換は `EventKitRepository` 側で行う。

| 要素 | 記法 | 変換先 |
| --- | --- | --- |
| 繰り返し | 毎日 / 平日 / 毎週月曜 / 毎週月水金 / 隔週火曜 / 毎月15日 / 毎月第2火曜 / 毎月最終金曜 / 毎月1日 / 3日ごと | `RecurrenceSpec`（frequency, interval, weekdays, daysOfMonth, weekOfMonth -1=最終） |
| 日付 | 今日 / 明日 / 明後日 / 来週水曜 / 11/20 / 20日 / 3日後 | `DateComponents`。過去日付は翌月・翌年へ繰り上げ |
| 時刻 | 9時 / 9:30 / 21時 / 午後3時 / 朝 / 昼 / 夜 | `DateComponents`。朝=8:00、昼=12:00、夜=20:00（設定で変更可）。日付を書かずに過ぎた時刻だけ書いたら翌日（繰り返しなら次の該当日） |
| リスト | #家族 / #仕事 | リスト名の前方一致（大文字小文字は無視）。`#` `@` を打つと候補を出して選べる。一致しなければエラーにして登録しない。省略時は既定リスト |
| 種別・カレンダー | @個人的 / @仕事（カレンダー名の前方一致）、@予定（既定カレンダー）、または「10時-11時」のような時間帯 | event。カレンダー名が一致しなければエラー |

入力例：

| 入力 | 結果 |
| --- | --- |
| 毎週月曜 9時 ゴミ出し #家族 | reminder、毎週月曜 9:00、リスト「家族」 |
| 毎月最終金曜 経費精算 | reminder、毎月最終金曜、時刻なし |
| 明日 15時 歯医者 | reminder、明日 15:00 |
| 金曜 10時-11時 面談 @個人的 | event、今週金曜 10:00–11:00、カレンダー「個人的」 |
| 牛乳買う | reminder、期日なし |

解釈できなかった語はタイトルに残し、プレビューのチップをタップして手で直せるようにする（MVPのチップは表示のみ。手直しは詳細編集で行う）。時刻付きリマインダーには期日時刻の `EKAlarm` を付ける（無いと純正アプリが通知しない）。パーサーは `protocol InputParser` にしておき、後でLLM実装と差し替えられるようにする。

## 同期・権限・制約

同期は自前で持たず、`EKEventStoreChanged` 通知を受けたら表示中の期間を再取得するだけにする。

- **権限**: `requestFullAccessToReminders()` と `requestFullAccessToEvents()`。Info.plistに `NSRemindersFullAccessUsageDescription` と `NSCalendarsFullAccessUsageDescription`。MacはApp Sandboxのカレンダー・リマインダーentitlementも必要
- **Googleカレンダー**: macOS/iOSの「インターネットアカウント」にGoogleを追加し、EventKit経由で読み書き。反映に数分の遅れあり
- **共有**: iCloud共有リストの中身は読み書き可能。メンバー招待は純正リマインダーで行う
- **通知**: リマインダーに `EKAlarm` を付ければ、純正アプリ側が通知する。自作アプリは通知を出さない。早期リマインダー（期日の N 分前）は負の相対オフセットの `EKAlarm` で表し、クイック入力の既定値は設定で選ぶ
- **繰り返し予定の編集**: `save(_:span:)` で `.thisEvent` / `.futureEvents` を選ぶ

EventKitから扱えない項目（確認時点はiOS 17〜18世代、着手時に最新SDKで再確認）：

- サブタスク、タグ、セクション、スマートリスト
- 共有リストの担当者
- 添付画像
- Google固有の項目（色、不在、勤務場所）。Meet のリンクは専用の項目としては取れず、メモに入ってくる案内から拾う

## 実装ロードマップとリスク

最初に「読める」を作り、次に「入れられる」を作る。各フェーズの終わりで純正アプリの代わりに日常使いして確かめる。

1. **基盤**: マルチプラットフォームプロジェクト作成、権限取得、`EventKitRepository` で予定とリマインダーを `TimelineItem` に変換
2. **今日タイムライン**: 表示・完了チェック・変更通知での再取得。ここでGoogleカレンダーと共有リストが見えることを確認
3. **クイック入力**: パーサー＋テーブルテスト、プレビューチップ、登録
4. **週表示と詳細編集**: 繰り返しの仮想展開、この回のみ/以降すべての編集、ドラッグでの日時変更
5. **Mac仕上げ**: キー操作（選択の移動・完了・編集・表示の切替）

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 日本語パーサーの表現揺れ | 入力の手間が残る | 実際に打った入力をログしてテストケースに追加、必要ならLLM実装 |
| 繰り返しリマインダーの将来分表示 | 週表示と純正アプリの見え方がずれる | 仮想アイテムは薄色・編集不可で区別 |
| OS更新でのEventKit仕様変更 | 権限やAPIの修正が発生 | EventKit周りをRepositoryに閉じ込める |
